# NE302 v4.3.1 OTA 更新指南

> [English](./NE302_v4.3.1_OTA_Update_Guide.md) | **中文**

> **适用场景**: 从 NE302 **v2.1.0** (commit `0198d97`) 升级至 **v4.3.1**
>
> **前置条件**: 设备正常运行旧版本固件，PC 端已准备好所有 OTA 固件文件
>
> ⚠️ **重要警告**: v4.3.1 对 Flash 分区表做了重新设计——Web 分区为**全新独立分区**（v2.1.0 无此分区）。升级必须严格按照本文档的**步骤和顺序**执行，跳过任何步骤或打乱顺序将导致设备 Web 界面无法访问。此外，v4.3.1 已切换至 STEdgeAI 4.x 发版线——**WiFi 固件必须升级至 `2.16.5.108`**，**AI 模型包必须是 4.x**。
>
> ⚠️ **数据丢失——内部存储将被重新格式化**: v4.3.1 同时迁移了内部 Flash 文件系统分区，APP 升级后首次开机时设备会**自动重新格式化**该分区，**内部 Flash 上存储的所有数据将被清空且无法恢复**——未插 SD 卡期间抓拍的照片、上传的文件、以及 MQTT TLS 证书文件。请务必在开始步骤一之前按[准备工作](#准备工作)中的说明完成备份。插有 SD 卡的设备不受影响（抓拍存储在卡上）；配置、WiFi 凭据等 NVS 数据全部保留。

## 升级概述

分区重新设计将原来混杂在其他分区中的 Web 资源独立为一个 Flash 分区。APP 升级后旧 Web 资源不再可用，设备将自动进入内置的 Web Recovery 恢复模式。升级需要按以下顺序完成：

```
旧版本（v2.1.0）
    │
    ├── 0. （未插 SD 卡使用的设备）先备份内部存储的照片/文件
    │      （APP 升级后首次开机会自动重新格式化内部存储，见准备工作）
    │
    ├── 1. 上传新 APP 固件（v4.3.1）→ 设备重启 → APP 升级完成
    │
    ├── 2. 连接设备 WiFi → 打开浏览器 → 进入 Web Recovery 模式
    │     （原因：Web 分区地址变更，旧 Web 资源不再可访问）
    │
    ├── 3. 在 Recovery 页面 → 上传新 Web OTA 固件（1.5.0.6）→ 页面自动恢复
    │     （Web 上传完成后自动重载 assets，无需重启）
    │
    ├── 4. 进入正常界面 → 系统提示 FSBL 版本不匹配 → 跟随引导升级（1.0.3.1）
    │     （如无提示：系统设置 → 固件升级 → 导入固件 → 高级选项 → FSBL 升级）
    │
    ├── 5. 重新连接 WiFi → 系统提示 WiFi 版本不匹配 → 跟随引导升级（2.16.5.108）
    │     （如无提示：系统设置 → 固件升级 → 导入固件 → 高级选项 → WiFi 升级）
    │     ⏳ WiFi 固件推送至芯片约需 1-3 分钟，请耐心等待
    │
    ├── 6. 上传 4.x 模型包（必需——AI 分区同样迁移了）
    │     （旧模型——无论是出厂默认还是之前 OTA 过的——新 APP 均不可见；
    │      完成本步骤前 AI 检测不可用）
    │
    └── 7. 升级完成 → 验证版本信息
```

### 为什么需要这样的流程？

| 变更点                         | 影响                                                   |
|-------------------------------|-------------------------------------------------------|
| Web 分区独立           | 旧版 APP 没有此分区概念，APP 升级后 Web 资源丢失 → 触发 Recovery |
| FSBL 期望版本校验 (1.0.3.1)     | APP 编译时指定 `EXPECTED_FSBL_VERSION=1.0.3.1`，不匹配则提示 |
| WiFi 固件 2.16.5.108 + SDK 升级 | APP 编译时指定 `EXPECTED_WIFI_VERSION=2.16.5.108`，不匹配则提示 |
| APP 主版本号 2 → 4（STEdgeAI 4.x）| 模型包前缀必须为 4.x，否则版本校验出现告警                      |
| AI 分区地址迁移                    | 旧模型包（含之前 OTA 过的）位于新 APP 不再读取的地址 → 步骤六为必做项 |
| 内部文件系统（LittleFS）分区迁移    | 首次开机自动重新格式化 → 内部存储的照片/文件/证书被清空，需提前备份 |

## 准备工作

### 需要准备的 OTA 固件文件

| 文件名                                  | 类型   | 说明                       |
|----------------------------------------|-------|---------------------------|
| 文件名                                  | 类型   | 说明                       |
|----------------------------------------|-------|---------------------------|
| `ne302_App_signed_v4.3.1.x_pkg.bin`     | APP   | 主应用程序 OTA 包            |
| `ne302_Web_v1.5.0.6_pkg.bin`            | Web   | Web 前端资源 OTA 包          |
| `ne302_FSBL_signed_v1.0.3.1_pkg.bin`    | FSBL  | 第一阶段引导程序 OTA 包        |
| `ne302_Wifi_flash_v2.16.5.108_pkg.bin`  | WiFi  | SiWG917 无线固件 OTA 包（必需） |
| `ne302_Model_4.x_pkg.bin`               | Model | AI 模型包，前缀 4.x（**必需**，见步骤六） |

### 先备份内部存储数据（未插 SD 卡使用的设备）

v4.3.1 迁移了内部 Flash 文件系统分区，APP 升级后首次开机会自动重新格式化。**未插 SD 卡使用**的设备，抓拍照片（`image_*.jpg`）及通过文件管理上传的文件都存放在内部 Flash 上，**升级后将被清空——开始步骤一之前请先备份**：

1. 打开设备 Web 管理界面，进入文件管理（相册）页面
2. 把需要保留的照片和文件逐一下载到 PC
3. 若配置了 MQTT TLS，同时保存 CA / 客户端证书与私钥文件——升级后需重新上传

插有 SD 卡的设备抓拍存储在卡上，无需备份。WiFi 凭据、系统配置等 NVS 数据升级后保留。

### 操作环境

- 一台可以连接设备 WiFi 热点的 PC / 手机
- 推荐 Chrome / Edge 浏览器（遇到缓存问题可使用无痕模式）

## 步骤一：上传新版本 APP 固件

> **目标**: 将 v4.3.1 APP 固件写入 Flash，重启后新分区表和新功能生效。

### 操作步骤

1. 确保设备正常运行旧版本固件，PC 已连接设备 WiFi 热点
2. 浏览器访问设备 Web 管理界面
3. 导航至 **系统设置** → **固件升级** → 点击 **导入固件**

![导入固件入口](images/step1_import_entry.png)

4. 在弹出的导入固件对话框中，点击 **APP 文件** 区域选择文件

![选择 APP 固件](images/step1_select_app.png)

5. 选择 `ne302_App_signed_v4.3.1.x_pkg.bin` 文件
6. 等待上传完成（上传过程中页面会显示进度）
7. 点击 **确认烧录** 按钮

![确认烧录](images/step1_confirm_burn.png)

8. 设备将自动重启，显示等待画面

### 预期结果

- 设备自动重启
- 等待约 5-15 秒后重新搜索设备 WiFi 热点

## 步骤五：WiFi 固件升级

> **目标**: 更新 SiWG917 无线芯片固件至 `2.16.5.108`。这是 v4.3.1 **必需**的步骤。

⚠️ **注意**: WiFi 固件推送至 SiWG917 芯片内部存储约需 **1-3 分钟**，这是整个流程中耗时最长的步骤。请耐心等待，**切勿中途断电**。

### 自动提醒方式

1. PC 重新连接设备 WiFi，进入 Web 管理界面 → **系统设置** → **固件升级**

2. 检查 **WiFi 版本** 一栏：
   - **Flash 版本** ≠ **运行版本**：出现提示图标
   - 二者一致但 ≠ **期望版本** (`2.16.5.108`)：出现提示图标

![WiFi 版本提示](images/step5_wifi_mismatch.png)

3. 点击提示图标 → **立即升级**

### 手动进入方式

**系统设置** → **固件升级** → **导入固件** → **高级选项** → **WiFi 固件升级**

### 操作步骤

1. 在 WiFi 升级页面，点击文件选择区域
2. 选择 `ne302_Wifi_flash_v2.16.5.108_pkg.bin` 文件

![选择 WiFi 固件](images/step5_select_wifi_file.png)

3. 文件上传完成后点击 **确认升级**
4. 弹出二次确认，确认后点击 **确认**

![WiFi 确认升级](images/step5_confirm_wifi.png)

5. 设备重启并开始 WiFi 固件推送

### 等待升级完成

设备重启后的行为：
- LED **快速闪烁**（WiFi 固件正在推送至 SiWG917 芯片）
- WiFi 热点会被断开，需要等更新完成后再次手动连接
- PC 端前端轮询（每 5 秒，最长 60 秒）检测设备是否恢复

如果前端未能检测到设备恢复，页面跳转至 **LED 指引等待页** (`/upgrade-waiting`)：

![LED 等待页面](images/step5_led_waiting.png)

根据 LED 状态判断：
- **LED 常亮** → 升级完成
- **LED 闪烁** → 升级进行中
- **LED 熄灭** → 异常或进入休眠了，尝试长按2S以上按钮唤醒

### 预期结果

- 固件升级页 WiFi 版本显示 `2.16.5.108`（Flash、运行版本一致）

## 步骤六：更新 AI 模型包

> **目标**: 上传 4.x 模型包，恢复 AI 功能。**从 v2.1.0 升级的每台设备都必须执行本步骤，不可跳过。**

### 为什么本步骤不可跳过

v4.3.1 迁移了 Flash 中的 AI 分区（旧：AI_Default @ `0x70900000`、AI_1 @ `0x70E00000`、AI_2 @ `0x71300000` → 新：AI_1 @ `0x70900000`、AI_2 @ `0x71100000`）。新 APP 只读取新地址，因此旧模型——无论是出厂默认的还是用户自行 OTA 的——对新固件都不再可见。根据设备槽位状态，固件升级页面会出现以下两种情况之一：

- **模型版本显示 2.x** —— 这是旧的*出厂默认*模型（其头部恰好位于新 AI_1 基址上）。2.x 模型无法在 STEdgeAI 4.x 运行时上运行，AI 检测仍不可用。
- **模型版本显示空白 / `0.0.0.0`** —— 旧固件上 OTA 过的模型位于新固件不再读取的地址。这是**预期现象，不代表升级失败**。

两种情况的处理方式相同——上传 4.x 模型包：

1. 进入 **系统设置** → **固件升级** → **导入固件**
2. 在对话框中选择 **AI 模型** 文件区域，选择 `ne302_Model_4.x_pkg.bin` 文件
3. 点击 **确认烧录** 并等待完成——烧录确认会自动重启设备
4. 重启后新模型加载、AI 检测恢复。模型只在开机时加载：若未点 **确认烧录** 就关闭了对话框，请手动重启（抽屉菜单 → **重启设备**）

> 遗留在 Flash 中的旧模型数据无害——后续模型升级（A/B 槽位）会逐步覆盖它，无需手动清理。

> ⚠️ **定制模型用户**：定制 2.x 模型包无法沿用，请先用 STEdgeAI 4.x 工具链重新打包自己的模型再上传；官方 `ne302_Model_4.0.0.0` 包只会恢复标准模型。

## 常见问题

### Q: 升级过程中断电了怎么办？

- **APP 升级断电**: A/B 分区保护机制——旧槽位固件完好，重新上电后自动启动。新槽位标记为 `UNBOOTABLE` 后系统自动回退
- **FSBL 升级断电**: FSBL 损坏将导致设备无法启动，需通过 JTAG/SWD 重新烧录
- **WiFi 升级断电**: 如果断电时正在推送 `.rps` 至芯片，重新上电后 WiFi 可能功能异常，可重新进入 WiFi 升级页面再次上传更新

### Q: Web Recovery 页面没有出现怎么办？

- 浏览器开无痕/隐私模式，重新输入设备 IP
- 清除浏览器缓存
- 换其他浏览器
- 确认 PC 已连接设备 WiFi 热点

### Q: FSBL / WiFi 升级提示没有出现？

手动路径：
- **FSBL**: 系统设置 → 固件升级 → 导入固件 → 高级选项 → FSBL 固件升级
- **WiFi**: 系统设置 → 固件升级 → 导入固件 → 高级选项 → WiFi 固件升级

### Q: 可以不升级 WiFi 吗？

**不建议**。v4.3.1 期望版本为 `2.16.5.108`，固件信息页会持续显示警告，且 SiWG917 无法获得本版本的修复。请升级。

### Q: 可以不升级模型包吗？

**不可以**（从 v2.1.0 升级时）。v4.3.1 迁移了 AI 分区，旧固件能看到的每一个模型——包括用户自行 OTA 的——都位于新固件不再读取的地址上，且 2.x 模型本身也无法在 4.x 运行时上运行。请按步骤六上传 4.x 模型包。只有已在新分区布局上运行 4.x 模型包的设备（如中间 4.x 构建）才可跳过。

### Q: 上传模型包后 AI 检测还是不工作？

模型只在开机时加载。**确认烧录** 会自动重启设备完成激活；若跳过了该步骤，请手动重启（抽屉菜单 → **重启设备**），再按步骤七校验 AI 模型版本。

### Q: 升级后抓拍的照片/上传的文件不见了？

v4.3.1 首次开机时自动重新格式化了内部 Flash 文件系统（分区迁移，见准备工作）。未插 SD 卡期间抓拍的照片和存放在内部 Flash 的文件无法恢复；SD 卡上的抓拍不受影响。若升级后 MQTT TLS 连接失败，请重新上传证书文件——原文件已随文件系统一并清空。

### Q: WiFi 固件升级后设备连不上？

1. 等待至少 3 分钟，观察设备 LED
2. LED 常亮但搜不到热点 → 尝试重启设备
3. 仍未恢复 → 通过 JTAG/SWD 烧录完整固件包
