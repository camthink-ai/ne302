## Change Summary

v4.3.1 is the largest release since v2.1.0: the Flash partition and memory layouts were restructured, the WiFi host stack was fully migrated, and a new capture-upload pipeline plus one-click bundle upgrade were introduced, along with extensive field-stability fixes. The most important changes are listed below; see the later sections for details.

### Highlights — New Features

1. **One-click bundle upgrade (OTA Bundle)** — `make pkg-bundle` packs all firmware images into a single file that upgrades the whole device in one web upload: the bundle carries its own partition table (layout migration), same-version entries can be skipped by choice, cross-model packages are hard-rejected, and the FSBL payload is staged and verified before it is written. Future full-device upgrades (including partition-table changes) no longer require handling each firmware one by one.
2. **WiFi subsystem overhaul** — host driver ported to the WiseConnect 4.1.1 SDK; new WiFi firmware OTA upgrade (paired firmware `2.16.5.108` with automatic mismatch guidance); WiFi region code (us / eu / jp / kr / cn); host-side AP DHCP server with sticky leases; plus a series of Si91x SPI-bus and host-stack hardening fixes.
3. **Capture-upload pipeline** — a new end-to-end capture-upload system: four upload modes (instant / batch / scheduled / local-only), MQTT batch publishing and webhook delivery, power-aware wake scheduling, SD hot-plug auto-switching, and a web management UI.
4. **Full HaLow (802.11ah) support** — mm6108 / mm8108 build-time chip switch, web configuration for radio parameters and extended country codes, and a web power-save switch (default off, paired dynamic-PS timeout).
5. **Web management UI overhaul** — a dedicated Web partition with automatic fallback into the built-in Web Recovery; new file management (Flash / SD) and a firmware-upgrade center (APP / Web / Model / FSBL / WiFi / bundle + expected-version checks); a major connection & stream-stability rework.
6. **AI & models** — unified build-time selection of the STEdgeAI 2.2 / 3.0 / 4.0 runtimes (this release line is 4.x); AI partitions enlarged to 8MB A/B slots; new capabilities including pose estimation, pointer-meter reading, instance segmentation, and BlazeFace face detection.

### Highlights — Fixes

1. **Black screen for late-joining live-preview clients** — the encoder emits SPS/PPS only once per session, leaving late joiners permanently black; clients are now keyframe-synced individually.
2. **Video-pipeline stop deadlock** — `video_pipeline_stop()` waited unbounded for a blocked node thread while holding the mutex, wedging the HTTP task; now bounded by 3 s with force-termination.
3. **Web connection & stream-stability overhaul** — one-request connections, static-asset etag/304 caching, FIFO-copied video frames, and a per-client WS send-buffer cap, eliminating `err_network` popups and smearing on the phone link.
4. **Startup-decision timer-thread stack overflow** — the startup-timeout callback ran on the tiny ThreadX timer thread where any printf/LOG overflowed into a HardFault; the decision now runs on a dedicated large-stack thread.
5. **Flash `stat` never set `st_mode`** — always 0, breaking directory detection and delete/status checks on internal Flash.
6. **JPEG tail truncation** — fixed DMA padding / EOI truncation causing bottom-mosaic and incomplete rendering in browser previews.

## ⚠️ BREAKING CHANGES

### 1. Flash Partition Table Redesign

The Flash partition layout has been restructured. **The new Web firmware must be re-uploaded**, and the system prompts when FSBL or WiFi firmware versions are mismatched.

| Partition  | Old (v2.1.0)           | New (v4.3.1)            | Change                                |
|-----------|------------------------|-------------------------|---------------------------------------|
| AI_1      | 5MB @ 0x70E00000       | 8MB @ 0x70900000        | Address moved forward, size doubled (merged AI_DEFAULT) |
| AI_2      | 5MB @ 0x71300000       | 8MB @ 0x71100000        | Address moved forward, size doubled (merged AI_3) |
| AI_DEFAULT | 5MB @ 0x70900000      | — Removed —             | Merged into AI_1                      |
| AI_3      | 8MB @ 0x71800000       | — Removed —             | Merged into AI_2                      |
| WEB       | — N/A —               | 1MB @ 0x71900000         | **New** independent Web partition      |
| WiFi FW   | 4MB @ 0x77C00000       | 3MB @ 0x71A00000        | Address moved forward, size adjusted   |
| LittleFS  | 64MB @ 0x72000000      | 32MB/96MB @ 0x71D00000  | Address changed, 64M/128M Flash support |
| Reserve2  | 28MB @ 0x76000000      | 4MB @ 0x73D00000/0x77D00000 | Address and size changed          |

### 2. PSRAM Memory Layout Changes

- **APP PSRAM boot**: PSRAM execution is now the only mode (conditional compilation removed). APP available space increased from 4032K to 4096K.
- **PSRAM SWAP region removed**: the 64KB PSRAM SWAP region at `0x903F0000` has been removed.
- **New SRAM_POOL region**: `0x34000000-0x341B1FFF` (1736K). The former SRAM APP space is now a general-purpose memory pool.
- **UNCACHED region adjusted**: start address moved from `0x341A0000` to `0x341B2000`.

### 3. WiFi Firmware Upgrade (Required)

- SiWG917 wireless firmware upgraded to **`SiWG917-B.2.16.5.1.0.8`** (encoded `2.16.5.108`), bundled with the new SDK.
- Older WiFi firmware (e.g., `2.14.5.x`) remains functional, but the device shows an upgrade prompt until the expected version is reached.
- New `EXPECTED_WIFI_VERSION` / `EXPECTED_FSBL_VERSION` compile-time version-check mechanism.

## New Features (Details)

### One-Click Bundle Upgrade (OTA Bundle)

Upgrade the entire device in a single upload, explicitly covering the "partition table changed" scenario (where old firmware cannot burn new firmware at the new addresses).

- **Packaging**: `make pkg-bundle` produces `ne302_Full_v<version>_bundle.bin` — a 4KB outer header (sub-firmware manifest + new partition table) followed by the existing `_pkg.bin` files in burn order (Model → Web → WiFi → APP → FSBL). Inner package formats are unchanged; CI produces the bundle artifact as well.
- **Entry point**: System Settings → Firmware Upgrade → Import Firmware → Advanced Options → **Bundle Upgrade** (`/import-bundle`).
- **Precheck burn plan**: after the file is selected, the device parses the bundle header, compares its own partition table and versions, and returns a burn plan (type / version / target address). **Same-version entries on unmoved partitions can be skipped by choice** (re-validated on the device; not all entries may be skipped; skipping WiFi also withdraws the push flag so a stale `.rps` is not pushed). FSBL may additionally be skipped only when the layout is completely unchanged; a **layout-changing bundle must contain an FSBL entry**, otherwise precheck rejects it.
- **Unified forced direct burn**: entries burn directly at the addresses from the bundle's own partition table (no AB slots); the OTA info partition is erased when the session starts, and SystemState is rebuilt from the new layout on the next boot.
- **Partition-drift warning**: every single-firmware package records a CRC of its build-time partition table in the OTA header; on mismatch with the running firmware's table, all single-firmware upgrade pages show a warning dialog (continue anyway, or switch to the bundle path which migrates layouts).
- **Device model gate**: OTA headers carry a `device_model` field (NE302 = 0x3020; unstamped legacy packages are allowed through), checked at both precheck and upload — cross-model firmware (e.g., an NE301 package on an NE302) is hard-rejected. The root Makefile's `DEVICE_MODEL` is the single source of truth.
- **Burn protections**: the FSBL payload is staged in PSRAM and only written after its CRC verifies; OTA uploads refresh the AP sleep timer so low-power mode cannot sleep mid-burn.
- **Frontend burn shield**: route blocker + `beforeunload` + a full-viewport mask prevent accidentally leaving during the burn; a stall of >4s shows an "erasing partition" hint (an 8MB AI partition erase takes seconds); a completion screen follows, with `/upgrade-waiting` guidance when the device is unreachable.
- Design document: `Script/docs/NE302_OTA_Bundle_Design_EN.md`.

### WiFi Firmware OTA Upgrade

- New OTA upgrade support for the SiWG917 WiFi firmware via the Web UI or system settings.
- **Two-stage upgrade flow**:
  1. **Upload stage**: streaming write to Flash (`WIFI_FW_BASE`), writing `flash_header_t` + `.rps` firmware binary. The OTA header is used for Web-side validation only and is NOT written to Flash.
  2. **Confirm stage**: sets NVS `wifi_mode=update` flag. On next reboot, `firmware_upgrade_from_flash()` pushes the `.rps` to the SiWG917 chip.
- **WiFi version detection**: the system reads both the Flash-stored WiFi firmware version and the chip's current running version, displaying both on the firmware upgrade page with automatic mismatch detection.
- **Expected version check**: when the Flash and running versions match but differ from the expected version, the Web UI shows an upgrade prompt dialog.
- **Upgrade waiting page**: pushing the WiFi firmware to the chip takes ~1–3 minutes. The frontend polls the device after reboot and redirects to an LED-guided waiting page (`/upgrade-waiting`) on timeout.
- `firmware_upgrade_from_flash()` and the WiFi firmware flash-header reads all hold the storage lock, avoiding concurrent-filesystem conflicts (including the XIP memory-mapped disable window); all error paths release resources properly.
- Firmware source is selected by trigger: **Web OTA uses Flash, recovery/CLI uses the SD file** (so a stray firmware on the SD card can no longer hijack a Web-uploaded one).
- New `wifi_mark_update_pending()` / `wifi_get_running_version()` / `wifi_get_flash_version()` APIs.

### WiFi Host SDK Upgrade (WiseConnect 4.1.1)

- WiFi host driver ported to the vendor **WiseConnect 4.1.1 SDK** (`SiliconLabs_SDK_4_1_1`; the previous 4.0.2 tree is retained for rollback). The SiWG917 chip firmware is unchanged at `2.16.5.1.0.8` — this is a host-side API migration, not a firmware upgrade.
- HAL adapted to the new SDK: `sli_si91x_driver_send_command` → `sli_wifi_send_command`, `sli_si91x_host_free_buffer` → `sli_buffer_manager_free_buffer`; the NCP host moved to an `rx_irq`/`rx_done` bus model with plain GPIO wake-read (the old `sem_sta` acquire stalled every SPI transaction).
- **EXTENDED scan HardFault fixed**: the firmware delivers each AP as a beacon (`result != NULL`, auto-accumulated into the SDK DB); only the empty-payload event means scan-done. A guard now skips intermediate beacons so AP/STA restore runs once — previously mid-scan re-ups triggered `0x19` busy → HardFault.
- **TWT auto-select** via the public v2 API (sync + async AP-negotiation wait); `low_power_mode_ctrl` now takes a full config (profile/dtim/monitor/beacon-miss), with new CLI `twt` and `lpwr` commands.
- **Host-bus & driver-layer hardening** (done together with the migration): `ulp_wakeup_init` moved from an infinite loop to bounded retry, desynced polls yield via periodic `osDelay`, host SPI transfers all go through the mutex + DMA-safe static buffers, chip-select is driven by peripheral NSS, 30 consecutive 0x19 TX failures auto-escalate into firmware-error recovery, and SDK asserts feed fault-safe recovery paths — a bus desync or firmware pipe wedge no longer hangs the device silently.
- An empty AP SSID after a config reset now auto-generates a `NE302_<mac>` default.

### WiFi Region Code

- New `sl_net_wifi_set/get_region_code` plus index/count helper APIs, supporting **us / eu / jp / kr / cn**.
- Applied on the next `sl_wifi_init`; both netifs must be DEINIT before setting; `wifi_country_code` persists to NVS.
- Exposed via Web API + WiFi region settings UI.
- `WORLD_DOMAIN` explicitly excluded (it breaks AP init with 0xF in CONCURRENT_MODE).

### Host-side AP DHCP Server with Sticky Leases

- Replaced the Si91x firmware DHCP server with a host-side lwIP implementation, giving the AP stable addressing.
- **Sticky leases**: MAC→IP bindings are cached after a station disconnects, so the station regains its original address on reconnect; when the lease table is full the oldest entry is evicted by LRU, and active clients are never evicted.
- Lease table protected by a mutex (tcpip thread vs WiFi event context); robust option parsing (PAD handling, bounds checks), replies padded to the RFC 300-byte minimum.
- netif (dual stack): NWP firmware DHCP feature bit disabled, host dhcpserver started on AP up; registered/unregistered on station join/leave.
- **Old-firmware compatibility (< 2.16.5)**: a one-shot firmware-version check falls back to the firmware DHCP server when the old firmware lacks host DHCP and the `IP_ADDRESS_INFO` notify.

### HaLow (802.11ah) Support

- Full HaLow Wi-Fi integration: quick connect, runtime radio sync, reconnect IP fix.
- Extended RegDomain country code support (end-to-end); PKA crypto hardware offload; IP configuration persistence; SPI6 clock auto-adaptation, relaxed EU duty cycle.
- **mm6108 / mm8108 dual-chip support**: build-time `HALOW_CHIP` selects the target silicon (default `mm8108`): `make` (mm8108) or `make HALOW_CHIP=mm6108`. Chip structure, firmware blob, and BCF configuration are gated by macros; both firmware sets coexist, with the unselected one stripped by `--gc-sections`.
- **Hardware mutual exclusion with PoE / 4G**: PoE (W5500 INT=PD15) and HaLow (BUSY=PA15) share the EXTI15 interrupt line and are hardware-exclusive; HaLow also conflicts with 4G, while PoE and 4G can coexist. Software enforces the exclusion — switching to or starting a link automatically stops the conflicting ones, startup inits only one of PoE/HaLow (PoE wins unless HaLow is preferred), and deinit clears the shim IRQ handlers so edges don't leak into the other stack.
- **Web-configurable power save**: HaLow chip PS is exposed as a radio settings switch (**default off**), persisted to NVS, applied at boot, and covered by JSON export/import; every power-save setting pairs `mmwlan_set_dynamic_ps_timeout` (the timeout is a standalone firmware parameter — without pairing, enabling PS at runtime would appear not to work); the SDK side is back to official power-save defaults, with runtime behavior fully controlled by the app-layer config.
- Web UI HaLow network configuration (radio parameters / country code / power-save switch, zh/en).

### Web Recovery System

- New `web_recovery` module: automatically enters a built-in recovery page when the Web firmware partition is empty or corrupted.
- The recovery page is a self-contained HTML page compiled into the APP firmware (no external resource dependencies), providing Web firmware upload functionality.
- After a successful Web firmware upload, `web_recovery_reload_assets()` is called automatically to reload assets from Flash and exit recovery mode — **no device reboot required**.

### Web Firmware Version Management

- Firmware upgrade page overhaul:
  - Import firmware dialog supports APP / Web / AI Model / Device configuration files.
  - Advanced options menu provides dedicated FSBL upgrade, WiFi upgrade, and **bundle upgrade** entry points.
  - New dedicated WiFi firmware upgrade page (`/import-wifi`) and bundle upgrade page (`/import-bundle`).
  - Firmware info page displays all component versions: APP / Web / AI Model / FSBL / WakeCore / WiFi.
- **FSBL / WiFi expected version check**: set at compile time; Web UI auto-detects mismatches and offers guided upgrade.

### AI Partition Restructuring & STEdgeAI 4.x Runtime

- `FIRMWARE_DEFAULT_AI` renamed to `FIRMWARE_AI_2`, with `FIRMWARE_AI_1` retained for AI model A/B dual-slot switching; AI partition sizes increased from 5MB to 8MB.
- **Unified STEdgeAI 2.2 / 3.0 / 4.0 runtime selection at build time**: application code is shared; select the version via `STEDGEAI_VARIANT`. `stedgeai.mk` automatically picks the matching NPU runtime library, device, and extra sources. Firmware and model packages must use the same variant.
- **Generated `stedgeai_version.h`**: `MODEL_STEDGEAI_VERSION_SUPPORTED` is now a generated header instead of a `-D` compiler flag, so dependency tracking catches STEdgeAI variant changes — no `make clean` required when switching variants.

### Capture-Upload Pipeline

A new end-to-end capture-upload system with date-partitioned record storage (`/captures/<state>/<date>/`) on Flash or SD card (auto / flash / sd / none selectable).
- **Four upload modes**:
  - **Instant** — snap and upload synchronously; on failure the record stays in `pending/` for automatic retry.
  - **Batch** — persist and flush when the pending count reaches a configurable threshold, or on the next wake tick.
  - **Scheduled** — flush at configured times of day.
  - **Local-only** — store locally and never upload.
- **MQTT batch-publish pipeline + Webhook** delivery support; MQTT publish payloads over 1800 B are rejected outright, avoiding the chip-side CE_TX buffer overflow that corrupts the shared heap.
- **Retry with configurable max attempts**; failed records can be retried individually or all at once from the Web UI.
- **Storage policies (WRAP / STOP)** with automatic cleanup; Flash capped at 256 records (`FLASH_MAX_RECORDS`), SD card unlimited.
- **Power-aware wake scheduling**: capture and upload-flush share a single scheduler with alarm override; on wake only the configured upload netif is brought up (saves multi-second bring-up and battery); the sleep path waits for any in-progress upload to finish before cutting power.
- **Network fail-fast**: skips the full network stack entirely when a wake cycle won't upload anything.
- **Web management UI**: capture settings page (config + records tabs), batch select / delete / retry, time-range filter, newest/oldest sort, and an upload-network selector (default or a specific netif).
- **NVS-persisted settings** + REST API for config, queue status, records CRUD, and batch operations.
- Storage-performance work to keep the capture/upload hot path fast: `lfs_fs_size` result cache, stat-before-mkdir, and a lightweight mount check.
- **SD hot-plug auto-switch (auto mode)**: the capture and status paths track SD insertion/removal in real time, so the storage target switches headless without any Web request; `storage_full` is now per-volume and reality-checked against live free space, so deleting files clears the stale storage-full banner.
- **`keep_sent_hours` keep-forever retention**: cap raised to **72000 (= keep forever)**, which is now the default — records are deleted only on storage-full or the record-count cap; `0` keeps its original meaning (delete on upload success).

### Storage & File Management

- Web-based file management: browse, upload, and delete files on Flash and SD card.
- Recursive folder deletion (including non-empty folders); blocking overlay + progress during deletion.
- File operation registration decoupled from LFS mount for improved boot robustness.
- **Format Flash from the file browser**; record-count cap enforced.

### SD Card Speed Mode Tools & High-Speed Boot

- New speed query / set / benchmark interfaces and CLI commands `sdspeed`, `sdswitch`, `sdrwtest` for speed diagnostics and performance evaluation.
- **50 MHz high-speed boot by default**: `HAL_SD_Init` no longer leaves UHS cards (without a 1.8 V transceiver) running at the out-of-spec Default Speed (~100 MHz at CLKDIV=0); the 50 MHz cap + CMD6 HS is enforced on every (re)insertion.
- `sdswitch` provides an overclock test mode (~100 MHz); the card is first switched back to Default Speed because HS+100 MHz is unstable on UHS cards.
- `MEM_FAST` internal memory pool enlarged from 184 KB → **512 KB**.

### Oversized Image Preview (Web)

- Image size is validated against the backend preview limit (`MAX_PREVIEW_SIZE_IMAGE = 2MB`) before serving the preview — the backend returns a `too_large` JSON for over-limit images, which previously rendered as a broken image.
- File manager shows a hint in place of the preview button; capture records replace the main preview button with a hint and apply `too_large` detection to inference-result previews.

### Crash, Camera & Factory Diagnostics

- **HardFault register dump**: on a hard fault the device prints CFSR/BFAR/MMFAR/HFSR plus PC/LR/SP to help triage crashes.
- **HardFault dump enhancements**: HardFault/MemManage now use naked-handler wrappers passing the real EXC_RETURN + entry SP (every after-the-fact C-level way of getting them was disproven); a shared `fault_dump_frames` dumps both the main frame and the other stack's `[alt]` frame, including R0–R3 registers and an OCTOSPI-region return-address BT walk so addr2line can resolve frames above the stacked PC/LR.
- **MPU MSP stack-overflow sentinel**: new MPU region 1 = a 256 B `PRIV_RO` guard at the stack bottom (`&_sstack`). An MSP overflow into the newlib heap below now trips MemManage instead of silently corrupting heap metadata; `MemManage_Handler` decodes CFSR/MMFAR and tags the guard-band trips.
- **`camdiag` CLI command**: reports camera pipe / buffer / frame state and DCMIPP error flags (pipe overflow, AXI transfer error) for camera debugging.
- **`factory hw [version]` command**: shows (factory partition first, user partition fallback) or sets the hardware version, keeping both NVS partitions in sync; default hardware version is now V1.0.

### Hardware Support

- Auto-adaptive dual-chip NOR Flash driver: auto-detects MX66 (1Gb) and GD55 (1Gb/512Mb).
- 64MB and 128MB Flash capacity support (`BOARD_FLASH_SIZE`).
- ISP grayscale mode with live IQ hot-swap on mode/grayscale change (no reboot).

### Networking

- 4G manual PLMN operator selection.

## Bug Fixes (Details)

### Network / PoE

- **Startup connection decision moved to a dedicated thread**: the startup-timeout timer callback ran on the tiny ThreadX timer thread, where any printf/log overflowed the stack and caused a HardFault. The decision now runs on a dedicated large-stack thread; the timer only sets an event flag.
- **AP startup no longer gated on cellular**: dropped the cellular-active ap-skip branch so AP bring-up is not blocked by 4G state.

### Wireless (WiFi)

- **LED indicator device name corrected**: `wifi_update_process` now uses `IND_EXT_DEVICE_NAME`, matching the LED device actually used by `device_service`.
- **AP boot-state race**: `device_service_start` previously set a blind ap-off that raced with the async ap-on on the netif thread. It now sets the startup indicator based on the actual AP state and no longer overrides an already-up AP.
- The MQTT client-id sentinel `AICAM-000000` is rewritten with a MAC suffix in `mqtt_build_topics` (the old timestamp scheme was unreliable).
- Per-interface netif flags: AP no longer sets `NETIF_FLAG_IGMP`.
- On connect failure the link is reset via `sl_wifi_disconnect`; `nm_get_netif_list` now negates a positive `sl_status` so it can't be misread as a count.
- eth_wan default interface: fixed the default handling when no cellular module is present.

### File Management / Storage

- Removed stale multi-select entries after single delete/rename.
- Flash directory deletion returns an explicit `DIR_NOT_EMPTY` error.
- **Flash `stat` now sets `st_mode`** (`S_IFDIR`/`S_IFREG`) — it was always 0, which broke directory detection and delete/status checks on internal Flash.
- **Flash mapping read protection**: guards raw XIP reads during the storage erase/write window when memory-mapped mode is disabled, so reads of the Flash-mapped region no longer trigger a BusFault.

### Upload (Upload Coordinator)

- Records with a missing source image move from `PENDING` (stuck forever) to `FAILED`.
- SD deletion falls back to `fx_directory_delete` for directories; silenced `FX_DIR_NOT_EMPTY` logs (best-effort empty-directory cleanup).
- Capture: runtime AI-result (inference) JPEG gated by `capture_storage_ai`.

### Image / Preview

- **JPEG buffer aliasing**: fixed buffer aliasing in capture and JPEG encoder.
- **JPEG tail fix**: `jpegc` trims DMA-padded `0x00` after EOI and re-appends EOI when the final `D9` byte is truncated. Fixes mosaic at the bottom of the browser preview and incomplete rendering.

### Web Frontend

- **Black screen for late-joining preview clients fixed**: the encoder emits SPS/PPS only once per session, so clients connecting afterwards never received the parameter sets — jmuxer's `readyToDecode` never set, frames silently dropped, and each frontend watchdog `hardRestart` built a fresh jmuxer → permanently black with an infinite loading loop. Each client now tracks `sps_synced`: late joiners skip delta frames and receive a composed `[SPS][PPS][IDR]` frame (annexB start codes re-inserted from the hub cache) at the next keyframe; join latency is at most one GOP (~1 s).
- **Connection & stream-stability overhaul**:
  - **One-request connections**: every response path sends `Connection: close` + drain so the browser never reuses a socket — fixes the `err_network` popups on the phone WiFi link during rapid tab switches.
  - **Static-asset etag / 304 caching**: CRC32-based etag + `if-none-match` → 304, shrinking the per-mount worker/importScripts re-fetch from ~273 KB to nothing.
  - **Video frames copied into a FIFO before the async web-task send**: fixes smearing from the send buffer being reused mid-flight.
  - **Per-client WS send-buffer cap**: dead connections no longer accumulate memory without bound.
  - **iOS MSE hardening + stream diagnostics**: sourcebuffer detach guards; a net-failure viewer + toast markers behind the `NET_DIAG` flag.
  - Silent `err_network` GET retry (1 s / 8 s backoff) to cross ~10 s radio holes.
- **WiFi scan dialog waits for scan completion**: the STA endpoint now exposes `scan_in_progress`, which the frontend polls until the background scan actually finishes — previously the reload mask closed on the first STA response and showed stale/empty results.
- **Distinct hint when a staged WiFi firmware doesn't match the expected version**: tells apart "staged but different version" from "expected version not yet reached".
- Improved FSBL import & burn flow with reboot feedback.
- WiFi reconnect changed from retry to **STA polling**.
- Stabilized MSE live preview, recovered stuck streams; improved iOS playback frame-following, added media tests; fixed black preview after a model upload.
- Fixed garbled error message display.
- Mobile layout fixes: select rows / the RTSP URL no longer stretch the page width; the HaLow "H" badge is rendered as a path instead of text; the device-tool skeleton aligns with the real layout; a stale `sourceopen` after a watchdog restart is ignored.

### Video Pipeline

- **`video_pipeline_stop()` deadlock**: stop waited unbounded for node threads; a node whose `process()` blocked indefinitely (capture/encoder/AI) wedged the HTTP task holding `pipeline->mutex` forever. Now bounded by a 3 s deadline, after which stragglers are force-terminated via `osThreadTerminate()`.

### Other

- **Fill light PWM brightness**: fixed brightness scaling.
- **Crypto cleanup**: removed unused si91x PSA crypto components; tidied mbedtls PKA port.
- `communication_type` reports the live active link, refreshed on every cached_info get.

## Improvements

- APP PSRAM boot is now the only mode (removed `BOOT_IN_PSRAM` conditional compilation); APP available space increased to 4096K.
- Flash SWAP region relocated from Flash to the start of the PSRAM region.
- CRC32 calculation switched from hardware CRC to software implementation, avoiding the hardware CRC peripheral endianness issue.
- **XSPI NOR flash read power-save (~5 mA)**: `storage_power_save()` toggles XSPI back into memory-mapped mode after each read, and a new `storage_lock_ext/unlock_ext` runs the same toggle on unlock. Applied across the storage, Web-asset, AI-model, and WiFi-firmware read paths so flash returns to its low-power state between accesses.
- Web firmware auto-reloads after OTA upload (no reboot needed), providing a smoother upgrade experience.
- Removed legacy si91x WiFi SDK code.
- **Build system — incremental build fix**: `write_if_changed()` only overwrites generated headers when content actually changes, preserving file timestamps so `.d`-based dependency checks don't trigger spurious rebuilds.
- **Build system — removed transitive `version.h` includes**: `#include "version.h"` moved from headers to the `.c` files that actually use version macros, preventing 9 source files from recompiling every time `version.h` changes.
- **Build system — bundle target & CI**: new `make pkg-bundle` target with packing/verify scripts (`ota_bundle_packer.py` / `verify_ota_package.py` bundle mode); CI publishes the bundle artifact and prunes stale versioned packages.
- APP version moved to the **4.3.1 release line** (STEdgeAI 4.x generation; major version overridden by `STEDGEAI_BIT` in `stedgeai.mk`). Web → **1.5.0.6**.
- **CI publishes the app ELF for crash symbolication**: the build artifact now includes the ELF, matching the HardFault register dump for addr2line resolution.
- RTC scheduler task stack enlarged 8K → 32K to cover the deep call frames of the HaLow connect + upload path.
- Removed the fast-capture orchestrator that was never wired onto the wake path (`quick_bootstrap.c` / `quick_network.c`).

## Known Issues

- WiFi firmware OTA upgrade push stage takes ~1–3 minutes. Do not power off during this process.
- Bundle burns do not use AB slots (forced direct burn). Do not close the browser page or power off during a bundle burn.
- Upgrading from v2.1.0 requires updating **in sequence**: APP → Web → FSBL → WiFi → Model. See the [OTA Update Guide](./NE302_v4.3.1_OTA_Update_Guide.md).

## Upgrade Notes

1. **Upgrading from v2.1.0**: the Flash partition table was redesigned — a **new independent Web partition** was added and the WiFi FW / AI partitions moved. Old Web assets become inaccessible after the APP upgrade, so the device enters Web Recovery and the upgrade **must follow the sequence** in the **[OTA Update Guide](./NE302_v4.3.1_OTA_Update_Guide.md)**: APP → Web recovery → Web → FSBL → WiFi → Model. Skipping or reordering steps leaves the Web interface inaccessible. Once on this release, future full-device upgrades can use the one-click bundle.
2. **WiFi firmware must be upgraded** to `SiWG917-B.2.16.5.1.0.8` (encoded `2.16.5.108`). The device compares the Flash-stored version against the chip's running version and guides the upgrade in the Web UI on mismatch.
3. **STEdgeAI moved to the 4.x generation**: APP major version = 4, so the model package prefix must be 4.x. A prefix mismatch triggers a version-check warning.
4. **FSBL must be upgraded to 1.0.3.1** (dual-chip NOR Flash auto-detection support; the APP carries a compile-time expected-version check).
5. **Firmware package model gate**: OTA headers carry the device model; cross-model packages (e.g., another product line's package) are rejected by the device. Unstamped legacy packages still work.
